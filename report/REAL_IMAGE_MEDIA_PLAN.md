# PT camera：media 和真实照片方案

## 1. 与 Silvia Ferrari 项目说明的对应

项目第4步允许 graphs、figures、videos 或其他 media；没有规定视频必交、视频时长或图片张数。第5步要求分析 media 为什么证明模型刻画了传感器性质及测量依赖。研究生另需从模型出发的数学分析。以下时长与数量都是制作建议，不是教师额外规定。真实照片不是硬性要求。

若使用真实传感器或已有模拟器，第3步仍要求自己的数学模型，并在第4–5步展示模型捕捉其行为的效果。将一张照片设成背景不构成真实传感器验证。

## 2. 推荐 media 成品

一个约2–3分钟的MP4 + 4–6张可用于报告的PNG/PDF图；另保存原始CSV、参数和随机种子。可只用图而不做视频，只要证据完整。推荐分屏：

- 左：世界/地面视图、相机位置、FOV、目标、障碍物；
- 右：模拟相机图像，标出目标ID、预测坐标、观测坐标和遮挡/出界状态；
- 底部：pan/tilt/高度/时间，以及当前实验的误差或可见状态曲线。

建议镜头顺序：

| 片段 | 改变什么 | 画面和对应论点 |
|---|---|---|
| 约15秒模型说明 | 不变 | 坐标系、相机参数、场景和测量定义 |
| 约30秒姿态扫描 | 分别改变pan和tilt | pan只旋转地面footprint；tilt改变形状；画面与目标集合随之改变 |
| 约20秒高度 | 高度单独改变 | 视场覆盖和目标投影尺度；垂直向下时面积理论A=abH²/f² |
| 约30秒目标与遮挡 | 分别移动目标、改变障碍物 | 进入/离开FOV、LOS中断；缺测显示 unavailable，不显示为零 |
| 约30秒验证 | 统计比较 | 理论曲线对比、预测–观测像素误差、噪声RMSE |
| 约15秒局限 | 不变 | 标注planar texture / synthetic target / real observations的来源 |

当前只完成pan动画、固定遮挡、噪声曲线和基础几何测试。这里其余片段为后续计划，不是现成结果。

## 3. 推荐真实生活场景：平坦地面上的标记物

用手机或普通相机拍摄教室/走廊/停车位的平坦地面。在地面贴8–12个可识别的标记，测量它们的平面坐标。推荐目标是地面标记或人的脚点；不要把人头、车辆顶部等离地面点直接当作Z=0。

收集资料：

1. 同一镜头、分辨率、焦距设置下的多张棋盘格标定照片，用OpenCV `calibrateCamera` 估计内参K和畸变；记录标定误差。不要把仿真的36×24mm尺寸直接用于手机相机。
2. 一张清晰的参考场景照片和地面标记的世界坐标。用 `undistort` 消除镜头畸变。估计单应至少需4个不共线点；最好有更多、分布广泛的点。
3. 至少保留若干未用于拟合的标记和独立拍摄的姿态图像作验证。不能用同4点同时拟合并声称独立验证。
4. 若只想做纹理演示，无需真实PT硬件。若要验证真实姿态变化，另外拍摄已知/独立估计姿态的多幅图像。没有角度/位姿参考时，不能宣称验证了电机响应或绝对pan/tilt精度。

单张平面照片的4点单应不足以独立恢复全部内参和姿态；必须区分平面配准、相机内参标定和姿态估计。

## 4. 三种真实图像接入路线

### A. 照片作为平面纹理（最贴合现有Z=0模型）

把真实地面照片映射到已知平面，再用虚拟相机的pan/tilt/高度生成新画面。对平面Z=0，若R是camera-to-world，C是世界坐标相机中心，K是与相机坐标约定一致的像素投影矩阵，则

\[
G=K[\,R^T e_1\quad R^T e_2\quad -R^TC\,],\qquad
\tilde x\sim G[X,Y,1]^T.
\]

参考图像到新图像的平面变换为

\[
H_{\mathrm{ref}\to\mathrm{new}}=G_{\mathrm{new}}G_{\mathrm{ref}}^{-1}.
\]

OpenCV `warpPerspective` 可做图像重投影；同时对原图全1 mask做同一映射，仅在有效区域显示纹理，并结合正深度条件。保留有效区域mask，防止边界插值被误认作真实内容。

此路线能改变高度和相机中心，但只保证已建模的平面正确。树、人、立体物体和障碍物背面不能由一张地面照片恢复。需要遮挡时，建立明确的三维障碍物/目标几何，或采用独立深度数据。照片里已有遮挡不能简单“移走”而恢复背景。

### B. 全景照片/同光心纯旋转（更像摄像头转动画面）

用同一固定光心拍摄全景/360照片，从全景按光线方向采样虚拟帧。全景投影需按实际格式做remap，不能把整张等距柱状全景直接当普通透视照片。它能表现pan/tilt，不能支持改变观察中心后的真实视差。

对普通透视参考照片，若光心严格不变且图像已去畸变，则任意深度静态场景的纯旋转映射为

\[
H_{\mathrm{ref}\to\mathrm{new}}
=K_{\mathrm{new}}R_{\mathrm{new}}^TR_{\mathrm{ref}}K_{\mathrm{ref}}^{-1}.
\]

普通单张照片只能支持原来拍到的方向；超出部分显示黑色/透明。不能靠平移裁剪或AI补图作为真实相机几何验证。机械PT转轴不一定经过光心，因此实际设备常有平移分量，需要标定轴位置或说明近似条件。

### C. 实际PT相机/相机云台（证据最强，额外工作最多）

在多个已知角度拍摄真实标记物，独立测量/估计相机姿态，比较数学模型预测像素和实际观测像素。需要相机内参、畸变、pan/tilt零位、旋转轴及光心偏置等信息。只有做控制相关实验时才需要讨论电机时序和响应；图像几何验证不必首先实现控制器。

## 5. 由图像到传感器输出

渲染图像与传感器测量需要分别定义。测量可选择标记中心、地面目标点或物体边框；本项目最省事且可验证的是已知平面标记中心。

- 虚拟真值：使用自己的projection模型得到目标坐标、FOV和LOS标志；
- 真实观测：手工点击标记中心，或用OpenCV角点/ArUco检测得到像素坐标；
- 输出表：frame,time,pan,tilt,height,target_id,u_pred,v_pred,u_obs,v_obs,visible,residual_px；
- 缺测用NaN及状态记录，模型可见和检测失败不要混为一类；
- 对每幅帧计算径向像素RMSE=sqrt(mean((u_pred-u_obs)^2+(v_pred-v_obs)^2))，报告有效点数，分别显示标定和验证帧。

像素原点与方向必须明确。当前图像平面图使用笛卡尔坐标；实际图像通常左上角为原点，行号向下。以固定显示约定为例，u=cx+sx*px，v=cy-sy*py；若使用标准OpenCV相机坐标，必须相应统一相机轴、旋转及内参，不能直接把两套坐标约定混在一起。

同一模型生成照片warp并叠加同一模型的目标，只证明内部几何一致，不能独立验证真实相机精度。真实验证必须使用未由该渲染器生成的观测。

保留现有NumPy/Matplotlib模型。新增OpenCV处理标定、单应、图像warp和标记；用ImageIO/FFmpeg导出MP4。无需先训练YOLO或上Unreal/Gazebo。推荐文件：
